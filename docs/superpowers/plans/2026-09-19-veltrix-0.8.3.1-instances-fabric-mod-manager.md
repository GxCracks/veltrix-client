# VELTRIX 0.8.3.1 Instances, Fabric & Mod Manager Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the current VELTRIX 0.8.3 redesign into a Windows-first multi-instance launcher test build (`0.8.3.1`) with persistent Microsoft sign-in, release-only version selection, Fabric-by-default instances, and one Modrinth/CurseForge mod manager while preserving the existing official Minecraft authentication and launch core.

**Architecture:** Keep the current launcher/auth/launch code as the base and add focused services around it: secure Windows secret persistence, an instance repository/manager, a release catalog, exact Fabric loader metadata, provider adapters for Modrinth and CurseForge, and a managed-mod install layer. UI pages consume those services; the launch coordinator is adapted only where instance-specific game directories and pinned Fabric loader versions require it. The website remains untouched.

**Tech Stack:** Java 21, Swing/AWT, Java `HttpClient`, existing `MiniJson`, PowerShell DPAPI bridge on Windows, Mojang version manifest, Fabric Meta API, Modrinth API v2, CurseForge REST API v1, Bash contract tests, GitHub Actions Windows packaging.

**Spec:** `docs/superpowers/specs/2026-09-19-veltrix-0.8.3-instances-fabric-mods-design.md`

## Global Constraints

- Product remains `VELTRIX Client` and keeps the approved 0.8.3 cyan-left / purple-right visual redesign.
- This implementation is a test build identified as `0.8.3.1`; do not create an official public release tag unless separately requested.
- Website files are out of scope: do not modify `index.html`, `style.css`, `script.js`, `news.json`, `privacy.html`, or GitHub Pages design assets.
- Home must not show the large account/login card from the current test build.
- All normal Minecraft entries with manifest type `release` are selectable; snapshots, `old_beta`, and `old_alpha` are excluded.
- New instances default to Fabric; Vanilla remains selectable.
- Every instance has its own `game` directory with isolated `mods`, `config`, `resourcepacks`, `shaderpacks`, `saves`, `screenshots`, `logs`, and options state.
- Microsoft passwords are never stored. Persist only the refresh/session material required for official OAuth renewal.
- Refresh tokens and the CurseForge API key must not be written plaintext to `launcher.properties`, ordinary JSON, logs, crash reports, or command lines.
- Windows secret persistence uses user-bound DPAPI semantics; secure-store failure must degrade to signed-out/not-connected state without crashing startup.
- Preserve Microsoft OAuth PKCE, Xbox Live, XSTS, Minecraft Services login, entitlement/profile checks, the current application-registration approval behavior, Java runtime detection, diagnostics, and crash logging.
- Do not bypass Minecraft Services `Invalid app registration` / allowlisting.
- Modrinth works without configuration.
- CurseForge is optional and uses `x-api-key`; when the key is missing/invalid, the provider is disabled without blocking Modrinth or launcher startup.
- Required mod dependencies are shown before download; optional dependencies are never installed silently.
- Manually added unknown mod JARs are never deleted or overwritten automatically.
- Network failures must not erase existing local instances or make the launcher unusable.

## Review Focus

1. **Corrupt/unavailable Windows secure store:** launcher must still open signed out, must not expose the ciphertext/plaintext secret, and logout must remain idempotent.
2. **Version/Fabric metadata offline after instances already exist:** local instances remain visible/selectable and Vanilla launch metadata already on disk is not deleted.
3. **Two instances using the same Minecraft release:** game directories, mods, saves, options, and managed-mod metadata must remain isolated with no path traversal outside the configured instances root.
4. **Provider partial failure:** Modrinth search still returns results if CurseForge is absent/invalid/offline, and CurseForge can still return results if Modrinth fails.
5. **Interrupted or malicious mod download:** temporary/partial files and unsafe filenames must never appear as installed JARs in the selected instance.

- [ ] **Step 3: Implement Windows DPAPI without command-line plaintext**

Use `powershell.exe -NoProfile -NonInteractive -Command -`; send plaintext only through STDIN. Protection script:

```powershell
$plain = [Console]::In.ReadToEnd()
$bytes = [Text.Encoding]::UTF8.GetBytes($plain)
$protected = [Security.Cryptography.ProtectedData]::Protect($bytes,$null,[Security.Cryptography.DataProtectionScope]::CurrentUser)
[Console]::Out.Write([Convert]::ToBase64String($protected))
```

Unprotect does the inverse. Persist ciphertext atomically at `configDir/secrets/<sanitized-key>.dpapi`; allow keys only `[a-z0-9._-]+`. Non-Windows/PowerShell/DPAPI failure returns `IOException`; startup catches it and continues signed out.
